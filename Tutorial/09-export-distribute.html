9 — Export & ship

Turn your project into a playable, sellable plugin in one click.

Pre-flight

Before exporting, make sure:

  • You've saved the project (Ctrl/⌘+S)
  • The Brand Lab fields are complete (display name, creator, version)
  • Every sample zone resolves to an existing audio file
  • Every layout knob/slider is bound to a real parameter
  • The default preset sounds the way you want it to (it's the first thing users hear)

Studio will warn if any of these are missing during export. Sample-export validation in particular blocks export if zones reference files that don't exist.

Exporting

  1. Top toolbar → Export Pack → Export Pack...

    A folder picker opens, defaulting to ~/Documents/<instrument>.patchcraft.

  2. Pick a destination folder

    The Studio writes the entire pack into that folder.

  3. Confirmation dialog

    If anything triggered a warning during export (missing samples, missing artwork, etc.), the dialog lists them. The pack is still usable; warnings are advisory.

What the exported folder contains

MyInstrument.patchcraft/
├── manifest.json        ← branding + engine + version
├── layout.json          ← GUI element list
├── parameters.json      ← parameter palette + defaults
├── presets.json         ← preset bank
├── mappings.json        ← sample zones (key/velocity/pad)
├── expansion.json       ← expansion metadata (which patches/presets belong)
├── assets/
│   ├── background.png   ← canvas background (auto-generated if missing)
│   ├── thumbnail.png    ← library tile artwork
│   ├── logo.png         ← player logo (if branded)
│   └── knobs/ sliders/ meters/ images/    ← custom filmstrips & artwork
├── samples/
│   └── *.wav            ← copied audio files referenced by zones
└── patches/
    └── *.json           ← per-patch full instrument state

If the project's background image is missing on disk, the writer renders a default 1280×800 hero image so the exported pack is always self-contained.

Sending to an existing expansion

If you've already shipped a Player and now want to add an expansion to it:

  1. Top toolbar → Export Pack → Send to Expansion Pack...

    Choose the existing pack folder. The current project's patches/presets append to that pack's expansion.json.

  2. Validation

    The writer checks that the engine matches and asset dependencies are satisfied; warns on conflicts.

  3. Distribution

    Ship just the updated expansion.json + new samples/ + patches/ as a small delta, or the full updated pack folder.

Two delivery models

A. Bundle the Player + your pack

Ship two things together:

  • PatchCraft Player.vst3 — the runtime (or your renamed/branded build of it)
  • MyInstrument.patchcraft/ — your exported pack folder

Customers drop both into their VST3 plugin folder. The Player auto-discovers nearby packs and loads yours on first run. The branded chrome (display name, logo, accent colour) renders so the plugin appears in their DAW with your identity.

B. Sell expansion packs for an existing branded Player

If you've already shipped a branded Player to a customer base, additional packs are smaller deliverables:

  • Just ship the new .patchcraft folder — they drop it next to their existing Player
  • The Library Browser inside the Player picks it up automatically
  • Smaller download, faster turn-around for new content

End-user experience

  1. Open DAW, instantiate Player VST3

    The plugin window appears with your branding (display name, tagline, logo, accent colour).

  2. Pick a preset

    From the Player's preset dropdown — your bank of named presets is right there.

  3. Play notes

    From a MIDI controller or DAW track. The instrument responds.

  4. Tweak knobs / sliders / pads

    All visible controls are real plug-in parameters — they show up in the DAW's automation list.

  5. MIDI Learn

    Right-click any knob → MIDI Learn → wiggle a hardware knob → it's bound. Learn settings save with the project.

  6. Browse expansions

    If you've shipped multiple packs, the user can switch between them from the Player's library browser.

Versioning & updates

Each pack has a version field in its manifest. Bump it before shipping a new build (1.0 → 1.1, etc.) so users can see they have an update available. Your delivery channel (your store, plugin.club, direct download) is responsible for getting them the new files.

Roadmap Pack signing, license activation, automatic update notifications, and plugin.club integration are on the roadmap. Today the export → distribute loop is manual.

Final checklist

  1. Test in a DAW

    Load the Player VST3 in Reaper / Live / FL Studio with your pack. Play notes. Try every knob. Verify host automation works.

  2. Test on a clean machine

    If possible, copy the bundle to a fresh user account or another machine — catches missing-asset bugs.

  3. License + readme

    Drop a README.txt and a LICENSE.txt next to the pack folder. Describe install steps and your terms.

  4. Ship it

    Zip the bundle, upload, get paid.
