12 - pScript automation

pScript is PatchCraft's human-readable automation language. It lets instrument builders connect notes, knobs, mod wheel movement, presets, and timers to live parameter changes without writing C++.

Current model: pScript is project-level, not stored directly on each knob. A knob triggers pScript when it is mapped to a parameter and that parameter changes in the Player.

How to attach pScript to a knob

  1. Create or choose a parameter

    Use a real DSP/Sample/FX parameter such as filterCutoff, delayMix, volume, or reverbMix.

  2. Bind the knob to that parameter

    On the Design canvas, select the knob and set its parameter assignment in the Inspector. The knob must control a real parameter.

  3. Generate a starter

    Right-click the selected control and choose Create pScript Handler For Selected Control, or use Design > pScript > Create pScript Handler For Selected Control. PatchCraft inserts a starter block using that control's real parameter id and range.

  4. Edit the behavior

    The generated block keeps the control's normal parameter mapping and adds script behavior. Replace the second set target with the sound parameter you want to affect.

  5. Compile and test

    Click Compile & Test. Fix any compile error before export.

  6. Export the Player

    The script is saved as pscript.txt in the pack. The Player loads it and runs events when presets load, notes play, controls move, or timers fire.

Smallest knob example

This runs when a knob mapped to volume moves. value is the knob's live parameter value.

when knob "volume" moves:
    set delayMix to value * 0.25

For a friendly parameter name, this works because Cutoff resolves to filterCutoff internally:

when knob "filterCutoff" moves:
    set delayMix to 0.20
Important: for knob events, value is the actual parameter value, not always 0.0 to 1.0. A volume knob may send 0.0 to 1.5. A cutoff knob may send 20 to 20000. Match your math to the parameter's range.

Knob range conversion

Use mapped when a source range should drive a different destination range. For knob/control events, value is the event source. Source and destination ranges can use common musical units such as Hz, dB, ms, st, and %.

# Cutoff range: 200 Hz to 12000 Hz.
# Map it directly to a useful delay mix range.
when knob "Cutoff" moves:
    set delayMix to value mapped 200 Hz..12000 Hz -> 0.05..0.45

Common recipes

Velocity opens the filter

when note starts:
    set filterCutoff to velocity mapped 0..127 -> 500 Hz..8000 Hz

Mod wheel adds performance motion

when modwheel moves:
    set vibratoDepth to modwheel mapped 0..127 -> 0.0..0.75
    set reverbMix to modwheel mapped 0..127 -> 0.05..0.35

One knob controls tone and space

when knob "Tone" moves:
    set filterCutoff to value
    let normal = (value - 200) / 11800
    set delayMix to normal * 0.25
    set stereoWidth to 0.85 + normal * 0.30

Safety reset when a preset loads

when preset loads:
    set volume to 0.85
    set delayFeedback to 0.32
    set reverbMix to 0.18

Conditional behavior

when note starts:
    if velocity > 100:
        set filterCutoff to 9000 Hz
    else:
        set filterCutoff to 1200 Hz

What is wired today vs. what needs polish

StatusFeatureNote
ReadyProject-level scriptsSaved as pscript.txt and loaded by the Player.
ReadyKnob eventsTriggered by mapped parameters in the Player.
ReadyNote, mod wheel, preset, timer eventsCovered by smoke tests.
Needs polishPer-control attachment UIThere is no right-click "Attach pScript to this knob" flow yet. The event attaches to the parameter, so two knobs mapped to the same parameter trigger the same script.
Needs polishMapping UI helpersThe language supports value mapped, but the editor still needs dropdown helpers so users do not have to type common ranges manually.
Needs polishPlayer compile errorsThe Player should show script compile errors instead of failing silently.
Reservedsmooth, play layer, turn effectParsed by the language, but not yet a reliable customer-facing workflow.

Recommended language direction

The language should stay readable enough for musicians but predictable enough for professional builders. The ideal authoring flow is:

control "Tone" affects filterCutoff:
    map value 0..1 to 200 Hz..12000 Hz
    also set delayMix to value * 0.25
    also set stereoWidth to 0.85 + value * 0.30

That is not the current syntax yet. It is the direction: named controls, plain verbs, explicit ranges, safe units, and obvious side effects.
